# 울림 (Ullim)

무료로 공개된 음장 기법을 모아 만든 음악 플레이어. 윈도우와 안드로이드가 **같은 화면 · 같은 음장 엔진**을 씁니다.
곡에 맞는 **가사**를 인터넷에서 찾아 노래에 맞춰 띄워 주고(시간 정보가 없는 가사는 **자동 싱크**), 사용자들이 고른 가사가 **모두의 앱에 함께 반영**됩니다.

## 내려받기 — [최신 릴리스](https://github.com/omokdie/ullim/releases/latest)

| 기기 | 파일 |
|---|---|
| 윈도우 10/11 (64비트) | `Ullim-Setup-<버전>.exe` — 실행하면 설치 · 시작 메뉴/바탕 화면 바로 가기 · 제어판에서 제거 |
| 안드로이드 7.0 이상 | `Ullim-<버전>.apk` — 이전 버전 위에 덮어 설치하면 재생목록 · 설정이 그대로 남아요 |

윈도우에서 "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행**. (코드 서명 인증서가 없는 새 프로그램이라 처음 한 번 뜰 수 있어요)

### 자동 업데이트 (1.1.0 부터)

1.1.1 이상을 한 번 설치하면 그다음 버전부터는 앱이 알아서 새 버전을 확인해요. 앱을 켜면 잠시 뒤(그리고 6시간마다) 이 저장소의
[`update/latest.json`](update/latest.json) 을 확인하고, 새 버전이 있으면 GitHub 릴리스에서 받아 **크기 · SHA-256 이 맞을 때만** 씁니다.

- **윈도우**: 새 설치 파일을 받아 두었다가 **앱을 닫을 때 조용히 설치**해요. 다음에 열면 새 버전. 바로 하려면 화면 맨 위 알림의 **[지금 다시 시작]**.
- **안드로이드**: 새 버전이 나오면 화면 맨 위에 알림이 떠요. **[받기]** 를 누르면 브라우저가 새 APK 를 받고, 받은 파일을 누르면 설치돼요
  (처음 설치할 때와 같은 방법, 재생목록 · 설정은 그대로). 앱이 APK 를 직접 받아 설치하는 기능은 Play 프로텍트가 '유해한 앱'으로
  막는 원인이라 1.1.1 부터 넣지 않았어요. 1.1.0 APK 는 이 때문에 설치가 막히니 **1.1.1 을 받아 주세요**.
- **설정 → 업데이트**에서 끄거나 지금 확인할 수 있어요. 재생목록 · 설정 · 가사는 업데이트해도 그대로예요.
- 1.0.x 에는 이 기능이 없어서, 1.1.1 만은 릴리스에서 한 번 직접 받아 덮어 설치해 주세요.

## 화면 (1.2.0 부터)

- **홈**: 위에서부터 장르 바로 가기(모든 곡 · 발라드 · 댄스 …) → **플레이리스트** 타일 2줄(PC 는 한 화면에 2×6, 휴대폰은 2×3 — **옆으로 밀면 더**)
  → **최근에 들은 곡** 6곡(**더보기 +** 로 전체) → **장르별 곡**(음악 파일의 장르 태그로 묶음, 옆으로 밀기 · 모두 보기).
- 타일을 누르면 플레이리스트 화면(큰 그림 · 재생 · 셔플 · 음악 추가 · ⋯ 메뉴). 최근 · 장르 · 모든 곡 목록도 같은 화면에서 재생하고,
  ⋯ → **새 플레이리스트로 저장**할 수 있어요. 앨범아트는 화면에 보이는 것만 작은 그림으로 만들어 저장해 둬요.
- 휴대폰은 아래 메뉴를 누르거나 **화면을 좌우로 밀어** 홈 · 음장 · EQ · 설정을 오가요(옆으로 밀리는 줄 위에서는 그 줄이 먼저 밀려요).
- **재생 막대**: PC 는 아래 전체, 휴대폰은 떠 있는 **미니 플레이어**. 누르면 **재생 화면**(큰 앨범아트 · **다음 트랙** · **가사** 탭,
  휴대폰은 아래로 밀어서 닫기).
- **재생 버튼**: 울림 표시 그대로 — 재생 중에는 안쪽 물결 → 두 겹 → 바깥 물결 순서로 신호가 퍼지듯 켜지고(1.2.3 — 0.4초마다 한 칸,
  화면을 덜 다시 그려 배터리 · 발열을 줄이려고), 멈추면 물결이 안으로 접히며 점이 세모(▶)로 서서히 바뀌어요(다시 재생하면 거꾸로).
  배터리 절약 중 · '동작 줄이기' 설정이면 물결은 멈춰 있어요.
- **아이콘 (1.2.2)**: 초록 · 노랑 · 파랑 그라데이션 울림 표시. **밝은 화면은 흰 바탕, 어두운 화면은 검은 바탕** — 앱 안 로고와 PC 창 아이콘은
  앱의 테마를, 안드로이드 홈 화면 아이콘은 휴대폰의 다크 모드를 따라요(바탕 화면 · 시작 메뉴 바로 가기 아이콘은 윈도우가 바꾸지 못해 흰 바탕).
- **안드로이드 알림 · 잠금 화면 (1.2.3)**: **무작위 · 이전 · 재생 · 다음 · 반복** 다섯 버튼(가운데 재생을 기준으로 좌우 대칭, 앱과 같은 모양의 아이콘).
  무작위 · 반복은 켜짐/꺼짐에 따라 아이콘이 바뀌고(반복은 전체 · 한 곡 · 안 함), 접힌 알림에는 이전 · 재생 · 다음. 안드로이드 13 이상은 시스템
  미디어 컨트롤의 4 · 5번 칸에 무작위 · 반복이 나와요. 예전 '닫기' 버튼 자리를 썼으므로 알림은 **멈춘 채 15분**이 지나면 저절로 닫혀요.
- **리퀴드 글라스**: 메뉴 막대 · 재생 막대가 뒤 화면을 흐리고 가장자리에서 살짝 휘어 보이게(굴절) 그려요. 휴대폰은 가볍게(아래 메뉴 · 미니 플레이어만),
  움직이는 효과 없이 크기가 바뀔 때만 계산. **배터리 절약 모드 · 배터리 20% 이하**면 자동으로 꺼지고, 설정 → 화면 → **유리 효과**(자동 · 풍부하게 · 가볍게 · 끄기).

## 플레이리스트

- 홈의 **새 플레이리스트** 타일(PC 는 왼쪽 메뉴의 **＋**)로 만들어요. 1.0.x 의 재생목록은 '재생목록' 플레이리스트로 그대로 옮겨져요.
- 다른 플레이리스트를 보거나 편집해도 **듣던 곡은 계속** 나와요. 보고 있는 목록에서 곡을 누르면 그 목록으로 재생이 넘어가요.
- 곡의 **⋯** (또는 오른쪽 클릭 · 길게 누르기): 다른 플레이리스트에 넣기 · 이 목록에서 빼기.
- 플레이리스트 화면 **⋯ → 편집**: 여러 곡을 골라 한꺼번에 넣기 · 빼기, **≡** 를 끌어 순서 바꾸기 (편집 중 Delete 키 = 고른 곡 빼기, Esc = 끝내기).
- **⋯ → 플레이리스트 관리**(홈의 **관리**): 이름 바꾸기 · 복사 · 순서 올리기 · 지우기. PC 앱은 **M3U/M3U8 내보내기 · 가져오기**(PLS, 옛 한국어 윈도우 .m3u 도 읽음).
- 위 막대의 **＋**: 파일 · 폴더 · 기기 음악 추가, **🔍**: 모든 곡에서 찾기 (플레이리스트 화면에서는 그 목록에서 찾기, PC 는 Ctrl+F).
- 같은 곡을 여러 플레이리스트에 넣어도 음악 파일은 그대로이고, 저장 공간도 거의 늘지 않아요.

## 가볍게 — 메모리 · 배터리 · 용량 (1.2.3)

- **메모리**: 앨범아트는 원본(3000px 면 풀었을 때 36MB) 대신 768px 로 줄여 쓰고, JPEG 는 처음부터 작게 풀어요. 목록에 곡을 넣을 때는
  그림 바이트를 읽지 않고, 자동 맞춤은 곡 전체가 아니라 15초씩 풀어 분석해요(4분 곡에 순간 100MB 넘게 → 몇 MB). 끈 음장 효과는 메모리에서 버리고,
  효과용 오디오 워클릿은 그 효과를 처음 켤 때 불러와요. PC 는 네트워크 · 오디오 서비스를 따로 띄우지 않고, 큰 일을 마치고 한가할 때 ·
  창을 내렸을 때 캐시(풀어 둔 그림 · 지난 곡 데이터)를 비워요.
- **배터리 · 발열**: 화면이 꺼져 있을 때(백그라운드 재생)는 시간 · 가사 표시를 갱신하지 않고 가사도 찾지 않아요(다시 보면 그때). 알림 · 잠금 화면은
  재생 · 멈춤 · 곡 · 무작위 · 반복이 바뀔 때만 다시 그리고 위치는 시스템이 흘려보내요(전에는 5초마다 알림을 새로 그렸음). 비주얼라이저가 없을 때는
  소리 분석기를 쉬게 하고, 꺼진 효과는 오디오 스레드에서 빠져요.
- **용량**: PC 설치 파일 105MB → 96MB. 음악 앱이 쓰지 않는 그래픽 부품(WebGPU 셰이더 컴파일러 · 그래픽 카드가 없을 때 쓰는
  소프트웨어 Vulkan, 약 32MB)을 빼고, 설치할 때 윈도우 기본 기능인 **실행 파일 압축**(`compact /EXE`)으로 프로그램 파일을 줄여
  설치 후 디스크 사용량이 약 310MB → 150MB 안팎(설정 → 앱 에 보이는 크기, NTFS 일 때)이에요. 읽을 때 윈도우가 알아서 풀어 주므로 동작 · 메모리는 그대로.
  업데이트로 설치해도 빠진 부품은 지워져요. 휴대폰 앱(APK)은 655KB → 389KB. 앨범아트 작은 그림은 **같은 그림을 한 번만** 저장해
  (한 앨범의 곡들은 보통 같은 그림) 앱 데이터가 앨범 수만큼만 늘어요 — 예전 버전이 곡마다 저장해 둔 것도 처음 실행 뒤 한가할 때 합쳐져요.

## 가사 — 함께 고쳐 가는 가사

1. 곡이 바뀌면 순서대로 찾습니다: **내가 고른 가사** → 음악 파일 속 가사 · 같은 이름의 `.lrc` → **다른 사용자들이 고른 가사** → [LRCLIB](https://lrclib.net) 자동 검색 (제목 · 가수 · 앨범 · 길이)
2. 가사가 없거나 엉뚱하면 가사 화면에서 **직접 검색** 또는 **틀린 가사 제보** → 맞는 가사를 누르면 바로 그 곡의 가사로 정해지고, **의견이 자동으로 올라가** 다른 사용자들에게도 그 가사가 나옵니다. ("가사가 없는 곡이에요", "틀렸다고만 알리기"도 같은 방식)
3. 로그인 · 계정이 필요 없습니다. 설정 → 가사 → **내가 고른 가사를 다른 사용자와 나누기**로 끌 수 있어요.
4. **한국 노래**: LRCLIB 에는 한국 노래가 영어 제목(벚꽃 엔딩 → Cherry Blossom Ending, 봄이 좋냐?? → What The Spring??), 소리 나는 대로 적은
   제목(바운스 → Bounce), 영어 가수 이름(아이유 → IU)으로만 올라간 경우가 많아요. 제목으로 못 찾으면 **가수(다른 표기 · 피처링 가수 포함)로 찾은 뒤
   곡 길이가 2초 안이고 가사 속에 우리 제목이 나오거나 제목 소리가 같을 때만** 받아들여요(흔한 낱말만 겹치는 다른 곡은 고르지 않음).
   파일 이름 '가수 - 제목', '[MV] …', '(Official MV)' 같은 꼬리도 걸러 읽어요.
5. **자동 맞춤(자동 싱크)**: 가사에 시간 정보가 없으면(일반 가사) 노래를 한 번 분석해(목소리가 나오는 구간 + 줄마다 글자 수) 줄마다 시간을
   맞춰, 싱크 가사처럼 노래에 따라 넘어가요. 처음에는 **대략**이라 몇 줄 어긋날 수 있어요 — 그럴 때 **지금 부르는 줄을 누르면** 그 줄에 맞추고
   나머지도 다시 맞춰요(두세 번이면 거의 맞음, 맞춘 것도 저장). 곡마다 한 번만 계산해 기기에 저장하고, 길게 누르기(오른쪽 클릭)로
   '이 줄부터 듣기 · 맞춘 시간 지우기'. 설정 → 가사 → **싱크 없는 가사 자동으로 맞추기**로 끌 수 있어요.
6. **백그라운드 · 모바일 데이터 (1.2.3)**: 앱을 보고 있지 않을 때는 곡이 바뀌어도 가사를 찾지 않고 다시 볼 때 찾아요. 휴대폰이 **모바일 데이터**로
   연결돼 있으면 가사를 자동으로 찾지 않아요(전에 찾아 둔 가사 · 파일 속 가사는 그대로 보임, 와이파이에 연결되면 자동으로 찾음, 가사 화면의
   **지금 찾기**는 언제든). 설정 → 가사 → **모바일 데이터에서 가사 불러오기**를 켜면 데이터에서도 찾아요.

```
앱 ──(익명 의견)──▶ ntfy.sh 메시지함 ──(30분마다)──▶ GitHub Actions ──▶ lyrics/overrides.json ──(2시간마다)──▶ 모든 앱
                      (12시간 보관)                  확인 · 투표 · 기록         (공용 가사 목록)
```

- **보내는 정보**: 곡 제목 · 가수 · 길이, 틀린/맞는 가사의 LRCLIB 번호, 앱 버전, 앱이 처음 만든 무작위 번호(한 사람 한 표용 — 공용 목록에는 해시로만 남음). 인터넷이 끊겨 있으면 앱에 쌓아 두었다가 다음에 보냅니다.
- **정하는 방법**: 한 사람(앱)은 한 곡에 한 표. 후보 점수 = "맞다" 표 − "틀리다" 표, 가장 높은 후보를 씁니다(동점이면 지금 가사 유지). "틀리다"가 더 많은 번호는 자동 검색에서 빠집니다.
- **엉뚱한 의견 막기**: 고른 가사가 LRCLIB 에 실제로 있어야 하고, 제목 · 가수가 비슷하거나 한쪽이 비슷하면서 곡 길이가 3초 안으로 같아야 바로 반영됩니다. 아니면 `needs-review` 이슈가 자동으로 열리고, 관리자가 `lyrics-approved` 라벨을 붙이면 반영돼요.
- GitHub 계정이 있다면 [이슈 양식](https://github.com/omokdie/ullim/issues/new?template=lyrics.yml)으로도 제보할 수 있습니다.
- 관리 방법은 [`lyrics/README.md`](lyrics/README.md) 참고.

## 1.3.0 — 새 음장 엔진 · 휠 · 재생 속도 · DAC · 코덱

- **끊김 · 지지직 없는 음장 엔진**: 효과를 브라우저 엔진(Chromium) 안의 네이티브 오디오 처리(C++ — 컨볼루션 잔향 · HRTF · 다이내믹스 ·
  바이쿼드 필터 · 2~4배 오버샘플링 파형 변형)로 다시 만들었어요. 예전에는 효과 대부분을 자바스크립트(AudioWorklet)로 계산해 휴대폰에서
  소리가 끊기고, 효과를 켜고 끄거나 볼륨을 바꿀 때 값이 갑자기 튀었어요. 이제는
  - 켜고 끄기 · 값 바꾸기는 모두 지수 곡선으로 부드럽게(0.12초 겹쳐 바꾸기, 효과 칸은 처음 켤 때 한 번만 끼워 넣음),
  - EQ · 음색 효과가 올린 만큼 **자동으로 미리 줄이고**(자동 프리앰프), 리미터는 기준 아래 소리를 **전혀 건드리지 않게**(웹 오디오 압축기가
    몰래 더하던 메이크업 이득을 되돌림), 마지막 안전망은 2배 오버샘플링 소프트 클리퍼,
  - 효과를 모두 끄면(리미터만 켜져 있어도) 효과 경로를 아예 쓰지 않아 **원음을 한 비트도 바꾸지 않아요**.
  측정(`test/fx_glitch_test.py`, 효과 25개를 켜고 끄며 녹음): 1.2.3 끊김 25번 · 640ms · 튐 2번 → 1.3.0 **0 · 0 · 0**.
  프리셋마다 요즘 가요처럼 꽉 찬 음원(-9 LUFS)에서도 안전망이 거의 일하지 않음(`test/preset_level_test.py`).
- **키 조절**: [Signalsmith Stretch](https://signalsmith-audio.co.uk/code/stretch/)(MIT, WebAssembly) — 음정만 바꿔도 소리가 맑아요.
- **휠(노브)**: 세기 · 양 · 시간처럼 연속으로 돌리는 값은 휠로. 음장 화면 위 **빠른 조절**(저음 · 고음 · 울림 · 입체감 · 선명도 · 보컬)은 휠을
  돌리면 해당 효과가 저절로 켜지고 끝까지 내리면 꺼져요. PC 는 위아래로 끌기 · 마우스 휠(Shift = 미세), 휴대폰은 좌우로 밀기,
  두 번 누르면 기본값.
- **재생 화면에 속도 · 음장 버튼**: **1.0×** 를 누르면 속도 창(0.5~2.0× 칩 · 휠 · 음정 유지), **음장** 을 누르면 바로 음장 효과 화면으로.

### 고음질 출력 (DAC) — 설정 → 고음질 출력

- **신호 경로**를 보여 줘요: 파일(예: `FLAC · 24bit · 96kHz · 무손실`, `DSD64`) → 앱 처리(32bit 실수 · 샘플레이트 · 원음 그대로/효과 N개) → 출력 장치.
  PC 재생 화면에는 `FLAC 24/96` 같은 형식 표시(고해상도면 강조색).
- **휴대폰 (안드로이드 14 이상)**: USB DAC 를 꽂으면 그 DAC 가 받는 **가장 높은 비트(32 → 24 → 16)와 샘플레이트(앱 출력의 정수배, 최대 192kHz)**로
  출력 형식을 정해요(`AudioMixerAttributes`, 권한 필요 없음). 목록에서 직접 고르거나 '안드로이드 기본'으로 되돌릴 수도 있어요. 블루투스는
  휴대폰이 코덱을 정하므로 LDAC 990kbps 를 고르는 방법을 알려 줘요.
- **PC**: 출력 장치(USB DAC · 오디오 인터페이스)를 고를 수 있고, 그 장치의 샘플레이트로 앱을 열어(다음 실행부터) 앱 안에서 한 번 더 바꾸지 않아요.
  Windows 공유 모드 32bit 실수로 내보내며, 장치 형식(24비트 · 192kHz 등)은 **소리 설정 열기**에서.
- 한계: 휴대폰 앱은 소리를 휴대폰 기본 속도(보통 48kHz)로 만들어 내보내요(WebView 구조). 고해상도 파일도 32bit 실수로 고품질 변환해 들리는 손실은 없어요.

### 코덱 엔진 — 더 많은 형식 (FFmpeg)

- 브라우저 엔진이 못 푸는 **DSD(DSF · DFF) · APE · WavPack · ALAC · AIFF · TTA · TAK · Musepack · WMA(무손실 포함) · AC-3 · E-AC-3 · DTS · TrueHD · MP2 ·
  CAF · Wave64 · Shorten** 을 [FFmpeg](https://ffmpeg.org) 7.1.1(LGPL 2.1+, 고치지 않음)을 WebAssembly 로 빌드한 엔진(`web/js/vendor/ullim-codec.wasm`,
  약 1.4MB)으로 풀어요. 확장자가 익숙해도(예: ALAC 가 든 .m4a) 브라우저 엔진이 못 풀면 자동으로 이 엔진으로 다시 시도해요.
- 푼 소리는 **무손실 FLAC**(원본이 16비트면 16비트, 그 밖은 24비트)으로 묶어 MediaSource 로 `<audio>` 에 넣어요 — 그래서 탐색 · 속도(음정 유지) ·
  음장 효과 · 크로스페이드 · 가사가 다른 형식과 똑같이 돼요. 5.1 채널은 스테레오로 섞고, DSD 는 88.2kHz(DSD64) · 176.4kHz(DSD128 이상, 휴대폰은 88.2kHz)
  24bit PCM 으로 바꿔요. 파일은 필요한 조각만 읽고(앞으로 20~30초만 미리 풀어 둠) 들은 부분은 버려 메모리를 적게 써요.
- 태그 · 앨범아트(APEv2 · ASF · DSF/AIFF 의 ID3)도 이 엔진으로 읽어요.
- 빌드 방법: [`codec/README.md`](codec/README.md). FFmpeg 소스는 릴리스 페이지에도 올려 둬요.

## 음장 효과 (40종 + 10밴드 EQ)

- **공간 · 입체**: 스테레오 와이드, 3D 서라운드, 가상 스피커(HRTF), 8D 회전, 하스 입체감, 헤드폰 크로스피드(bs2b)
- **잔향 · 에코**: 리버브(공간 크기 · 흡음 · 넓이 — 합성 임펄스 응답 컨볼루션), 공간 시뮬레이션(콘서트홀·대성당 등 7종, 컨볼루션), 에코·딜레이(핑퐁)
- **음색 · 저음**: 베이스 부스트, 가상 저음, 초저음 생성, 트레블, 라우드니스, 크리스탈라이저, 익사이터, 진공관 웜
- **음량 · 다이내믹**: 컴프레서, 야간 모드, 볼륨 평준화, 리미터
- **보컬**: 보컬 제거(노래방), 보컬 강조
- **변조**: 코러스, 플랜저, 페이저, 트레몰로, 비브라토, 오토 팬, 로터리 스피커
- **속도 · 키**: 재생 속도(음정 유지), 키 조절(±12 반음, Signalsmith Stretch)
- **특수 효과**: 라디오·전화, 수중, 로파이·비트크러셔, LP 레코드, 오버드라이브
- **채널**: 좌우 밸런스, 모노, 좌우 바꾸기

사용한 공개 기법 · 엔진: 브라우저 엔진 내장 네이티브 처리(ConvolverNode · PannerNode HRTF · DynamicsCompressor · BiquadFilter · IIRFilter · WaveShaper),
bs2b 크로스피드 공식(MIT), RBJ Audio EQ Cookbook 필터, Signalsmith Stretch(MIT, 키 조절), MaxxBass 방식 가상 저음(비선형 배음), 옥타브 분주 초저음,
샘플 차분 크리스탈라이저, 합성 임펄스 응답(초기 반사 + 주파수별 감쇠). 코덱은 FFmpeg(LGPL 2.1+). 그 밖의 코드는 모두 새로 작성했습니다.
